# قالب‌های پیامکی SMS.ir — راه‌اندازی

## چرا این کار لازم است

پیامک کد ورود (OTP) همیشه درست کار می‌کرد چون از **API قالب‌محور (Verify)** ارسال
می‌شود — این API روی خط اختصاصی سایت سوار نیست؛ SMS.ir خودش آن را از استخر خطوط
خدماتی‌اش می‌فرستد. مستندات رسمی SMS.ir هم صریحاً می‌گوید این روش برای
«اطلاع‌رسانی وضعیت سفارشات» هم ساخته شده، نه فقط کد ورود.

بقیهٔ پیامک‌ها (پیش‌فاکتور، سفارش، هشدار قیمت) روی **ارسال متن آزاد** بودند که
به نوع و اعتبار خط تنظیم‌شده حساس است — دقیقاً همان چیزی که باعث قطعی اخیر شد.

**راه‌حل:** هر پیامکِ ساخت‌یافته را هم به همان روش قالب‌محور OTP منتقل می‌کنیم.
کد این کار از قبل آماده و deploy شده — فقط باید قالب‌ها را در پنل SMS.ir بسازید
و شناسهٔ هرکدام را به من بدهید.

## چرا دور اول رد شد و چه چیزی عوض شد

SMS.ir سه قالب (هشدار قیمت، تأیید سفارش، ثبت درخواست) را رد کرد با این دلیل:
باید از **متغیر نام مشتری** برای شخصی‌سازی متن استفاده شود، و کنار هر متغیر در
پنل باید یک توضیح کوتاه دربارهٔ آن متغیر نوشته شود.

هر دو مورد اصلاح شده:

1. **همهٔ قالب‌های مشتری‌محور** حالا با `#NAME# عزیز،` شروع می‌شوند. اگر نام
   مشتری در سیستم ثبت نشده باشد (سرنخ بدون نام)، کد به‌جای خالی گذاشتن این
   بخش، به‌طور خودکار «مشتری» را جایگزین می‌کند — یعنی پیامک هیچ‌وقت با یک جای
   خالی یا نام شکسته نمی‌رود.
2. زیر هر قالب، پایین همین سند، یک **ستون «توضیح برای پنل»** اضافه شده — دقیقاً
   همان متنی که باید در پنل SMS.ir، کنار هر متغیر، در کادر توضیحات وارد کنید.

## نحوهٔ کار (چیزی که در کد پیاده شده)

هر پیامک یک متغیر محیطی اختیاری دارد. **تا وقتی آن را تنظیم نکنید، همان روش
قبلی (ارسال متن آزاد روی خط) دقیقاً مثل الان کار می‌کند — هیچ‌چیز خراب نمی‌شود.**
به محض این‌که شناسهٔ قالب را بدهید و من متغیر را تنظیم کنم، همان پیامک بی‌درنگ
(فقط با ری‌استارت، بدون rebuild) به روش قالب‌محور سوئیچ می‌کند.

## مراحل ساخت هر قالب در پنل SMS.ir

۱. وارد پنل کاربری SMS.ir شوید.
۲. مسیر: **برنامه‌نویسان ← ارسال سریع (Quick Send)** ← ایجاد قالب جدید.
۳. متن قالب را دقیقاً همان‌طور که پایین آمده paste کنید — متغیرها باید بین
   دو علامت `#` باشند و **نام هر متغیر باید حرف‌به‌حرف با ستون «پارامتر» زیر
   یکی باشد** (بزرگ/کوچک بودن حروف هم مهم است).
۴. **برای هر متغیر، در کادر توضیحاتِ همان متغیر** (پنل SMS.ir این کادر را کنار
   هر `#متغیر#` نشان می‌دهد)، متنِ ستون «توضیح برای پنل» را دقیقاً paste کنید —
   همین بخش بود که دور قبل خالی مانده بود و باعث رد شدن سه قالب شد.
۵. تأیید قالب توسط SMS.ir انجام می‌شود (معمولاً چند دقیقه تا چند ساعت).
۶. بعد از تأیید، عدد **شناسهٔ قالب (Template ID)** را از پنل بردارید و برای من
   بفرستید — نام هرکدام را هم بگویید تا در جای درست بگذارم.

## قالب‌ها (به ترتیب اولویت)

### ۱. صدور پیش‌فاکتور — `SMSIR_TEMPLATE_ID_PROFORMA_ISSUED`
مهم‌ترین قالب؛ لحظهٔ صدور قیمت نهایی برای مشتری.

```
آهن‌تایم: #NAME# عزیز، پیش‌فاکتور شما صادر شد. مبلغ: #AMOUNT# تومان. اعتبار تا #EXPIRY# ساعت ۱۱:۰۰. مشاهده: ahantime.com/proforma/#REF#
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| AMOUNT | ۷۸۲٬۶۵۰ | مبلغ نهایی پیش‌فاکتور به تومان |
| EXPIRY | ۱۴۰۵/۰۴/۱۳ | تاریخ انقضای اعتبار پیش‌فاکتور |
| REF | PF-14050411-0001-ABCDEF | کد پیگیری پیش‌فاکتور |

### ۲. ثبت درخواست (بدون قیمت) — `SMSIR_TEMPLATE_ID_PROFORMA_REQUEST`
وقتی مشتری فقط درخواست می‌فرستد و هنوز قیمتی صادر نشده.

```
آهن‌تایم: #NAME# عزیز، درخواست شما ثبت شد. کارشناسان به‌زودی تماس می‌گیرند. مشاهده: ahantime.com/proforma/#REF#
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| REF | PF-14050411-0002-ABCDEF | کد پیگیری درخواست |

### ۳. تأیید سفارش — `SMSIR_TEMPLATE_ID_ORDER_CONFIRMED`
لحظهٔ تبدیل سرنخ به سفارش (فقط همین یک لحظه — مراحل بعدی حمل، قالب‌های زیر را دارند).

```
آهن‌تایم: #NAME# عزیز، سفارش شما ثبت شد. کد رهگیری: #REF#. پیگیری در ahantime.com/track
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| REF | OR-14050411-0001-ABCDEF | کد رهگیری سفارش |

### ۳-الف. پیشرفت وضعیت سفارش — `SMSIR_TEMPLATE_ID_ORDER_STATUS`
هر بار وضعیت سفارش به «تأییدشده»، «بارگیری» یا «در حال حمل» می‌رود (به‌جز خودِ
«تحویل» که قالب جدا و گرم‌تری دارد — پایین‌تر).

```
آهن‌تایم: #NAME# عزیز، وضعیت سفارش #REF# به «#STAGE#» تغییر کرد. پیگیری: ahantime.com/track
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| REF | OR-14050411-0001-ABCDEF | کد رهگیری سفارش |
| STAGE | بارگیری | مرحلهٔ تازهٔ سفارش در فرایند حمل |

### ۳-ب. تحویل سفارش — `SMSIR_TEMPLATE_ID_ORDER_DELIVERED`
مهم‌ترین لحظهٔ حمل از دید مشتری؛ قالب جدا با لحن قدردانی، نه فقط «وضعیت تغییر کرد».

```
آهن‌تایم: #NAME# عزیز، سفارش #REF# با موفقیت تحویل داده شد. از خرید شما سپاسگزاریم.
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| REF | OR-14050411-0001-ABCDEF | کد رهگیری سفارش تحویل‌شده |

### ۳-ج. ثبت کد رهگیری — `SMSIR_TEMPLATE_ID_ORDER_SHIPPING`
لحظه‌ای که کارشناس شمارهٔ رهگیری واقعی را وارد می‌کند (نه فقط نام شرکت حمل به‌تنهایی).

```
آهن‌تایم: #NAME# عزیز، سفارش #REF# با #CARRIER# ارسال شد. کد رهگیری: #TRACKING#
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| REF | OR-14050411-0001-ABCDEF | کد رهگیری سفارش |
| CARRIER | باربری تیپاکس | نام شرکت حمل‌کننده |
| TRACKING | TIP-998877 | شمارهٔ رهگیری مرسوله نزد شرکت حمل |

### ۳-د. لغو سفارش — `SMSIR_TEMPLATE_ID_ORDER_CANCELLED`
وقتی سفارش لغو یا آرشیو می‌شود.

```
آهن‌تایم: #NAME# عزیز، سفارش #REF# لغو شد. برای اطلاعات بیشتر با پشتیبانی تماس بگیرید.
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| REF | OR-14050411-0001-ABCDEF | کد رهگیری سفارش لغوشده |

### ۴. هشدار قیمت — `SMSIR_TEMPLATE_ID_PRICE_ALERT`
وقتی قیمت کالا/شاخص به آستانه‌ای که کاربر تعیین کرده می‌رسد.

```
آهن‌تایم: #NAME# عزیز، #LABEL# به #VALUE# تومان رسید (هدف شما: #DIR# #THRESHOLD#). ahantime.com/market
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| LABEL | میلگرد ۱۴ آجدار | نام کالا یا شاخصی که هشدار روی آن تعریف شده |
| VALUE | ۳۵٬۲۰۰ | قیمت لحظه‌ای که هشدار را فعال کرد |
| DIR | زیر (یا: بالای) | جهت هدف قیمتی کاربر (پایین‌تر یا بالاتر از آستانه) |
| THRESHOLD | ۳۶٬۰۰۰ | آستانه‌ای که کاربر برای هشدار تعیین کرده |

### ۵. یادآوری انقضای پیش‌فاکتور — `SMSIR_TEMPLATE_ID_PROFORMA_REMINDER`
یادآوری خودکار ۲۴ ساعت قبل از انقضا.

```
آهن‌تایم: #NAME# عزیز، پیش‌فاکتور #AMOUNT# تومانی شما تا #EXPIRY# معتبر است. برای نهایی‌کردن: ahantime.com/proforma/#REF#
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری، برای شخصی‌سازی پیامک |
| AMOUNT | ۷۸۲٬۶۵۰ | مبلغ پیش‌فاکتور به تومان |
| EXPIRY | ۱۴۰۵/۰۴/۱۳ | تاریخ انقضای اعتبار پیش‌فاکتور |
| REF | PF-14050411-0001-ABCDEF | کد پیگیری پیش‌فاکتور |

### ۶. یادآوری تماس (داخلی، اختیاری) — `SMSIR_TEMPLATE_ID_CALLBACK_REMINDER`
این یکی برای **خود کارشناس** فرستاده می‌شود، نه مشتری — اولویتش پایین‌تر است
و می‌توانید فعلاً از آن صرف‌نظر کنید؛ تا وقتی قالبش نباشد، همان پیامک قبلی
(با نام و شمارهٔ مشتری) روی خط ادامه می‌یابد. NAME اینجا نام همان مشتری/سرنخی
است که باید تماس گرفته شود، نه نام کارشناس — هم نیاز پنل به متغیر نام را برطرف
می‌کند، هم برای خودِ کارشناس مفیدتر است.

```
آهن‌تایم: یادآوری تماس با #NAME# برای سرنخ #REF#. پنل: panel.ahantime.com/desk
```

| پارامتر | مثال مقدار | توضیح برای پنل |
|---|---|---|
| NAME | رضا کریمی | نام مشتری/سرنخی که باید با او تماس گرفته شود |
| REF | LD-14050411-0003-ABCDEF | کد سرنخ در سیستم |

## بعد از ساخت هر قالب

فقط شناسهٔ عددی (Template ID) هرکدام را برایم بفرستید — من متغیرهای محیطی را
روی سرور تنظیم و سرویس را ری‌استارت می‌کنم (rebuild لازم نیست). می‌توانید
قالب‌ها را یکی‌یکی بفرستید؛ هر کدام که برسد همان لحظه فعال می‌شود، بدون تأثیر
روی بقیه.

## نکتهٔ محدودیت مقدار پارامتر

SMS.ir طول هر مقدار پارامتر را حداکثر ۲۵ کاراکتر می‌پذیرد. کد از قبل هر مقدار
طولانی‌تر را با `…` کوتاه می‌کند (`truncateParam` در `smsir.ts`) تا ارسال هیچ‌وقت
به همین دلیل رد نشود — رفتار مطلوب همین است، نیازی به دخالت نیست. مقدار NAME هم
از همین قاعده پیروی می‌کند: اگر نام مشتری در سیستم طولانی‌تر از ۲۵ کاراکتر باشد،
همان‌جا کوتاه می‌شود.
